## 📝 Daily Events

### ([Customer Portal API](../../projects/customer-portal-api.md)) Symfony Messenger Implementation

Put yesterday's research into practice today. Implemented the async email notification system using Symfony Messenger. Decided to start with the Doctrine transport (database) since it's the simplest to set up and we don't need the complexity of Redis or RabbitMQ yet.

Created a `SendOrderShippedNotification` message class and a corresponding message handler. The handler uses the Mailer component to send the actual email. Added tests for both the message creation and the handler logic.

One thing I learned: the importance of making messages serializable. Had to be careful about what data I put in the message class - can't just pass entire entities. This is a good Symfony/async processing lesson that I'll remember.

The implementation works well. Tested it locally and the emails are being queued and processed correctly.
